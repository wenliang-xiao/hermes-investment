## 一、SilverQuantStrategy（组件化策略）

### 1.1 核心逻辑（一句话）

> **多组件风控系统：评分驱动建仓 + 多个独立清仓组件（硬止损、回撤止盈、MA死叉、评分下滑）并行判断，任一组件触发即卖出。**

### 1.2 建仓规则

| 维度 | 规则 | 阈值/参数 |
|------|------|-----------|
| **候选池** | 非持仓标的按评分降序排列 | TOP 5 |
| **评分门槛** | 评分 ≥ 5.0 | `entry_threshold = 5.0` |
| **仓位上限** | 固定槽位数 | `max_positions = 8` |
| **单笔金额** | 固定 ¥30,000/槽位 | `slot_cap = 30000` |
| **最小手数** | 100股（A股最小交易单位） | `max(100, int(30000/price/100)*100)` |
| **现金约束** | 现金不足则缩量，缩量后仍不足则跳过 | `cost > self.cash → continue` |
| **趋势过滤** | **无**（与面基不同，SilverQuant不做趋势过滤） | 无 MA20/MA60 判断 |

**关键观察**：SilverQuant 建仓逻辑与面基几乎相同（评分TOP5→5.0门槛→固定¥30K），唯一区别是**去掉了趋势过滤**（面基有 `if ma60_dev <= ma20_dev and score < 5.5: continue` 的均线纠偏）。

### 1.3 清仓规则（4个独立卖出组件）

SilverQuant 最核心的差异化在于清仓端——每持仓标的在每个交易日依次检查 4 个卖出信号，**任一满足即触发卖出**，优先级从高到低：

| # | 组件名 | 触发条件 | 数学公式 | 备注 |
|---|--------|----------|----------|------|
| 1 | **HardSeller**（硬止损） | 浮动亏损 ≥ -8% | `(price - entry) / entry * 100 ≤ -8` | 最优先，无任何豁免条件 |
| 2 | **FallSeller**（峰值回落） | 从持仓最高点回落 ≥ -12% | `(price - peak) / peak * 100 ≤ -12` | 保护浮盈，防止盈利变亏损 |
| 3 | **MASeller**（均线死叉） | MA20偏离度 < MA60偏离度 **且** 亏损未达-5% | `ma20_dev < ma60_dev AND pnl_pct > -5` | 附加"不亏太多"条件，避免已严重亏损时因均线信号止损 |
| 4 | **ScoreDropSeller**（评分下滑） | 当前评分 < 4.5 | `score < 4.5` | 基本面逻辑恶化，无任何附加条件 |

**优先级与互斥**：按 1→4 顺序检查，触发一个就执行 `del` + `continue` 跳到下一个标的，**不叠加**。

### 1.4 仓位管理

| 维度 | SilverQuant | 说明 |
|------|-------------|------|
| **模式** | 固定槽位（Equal-Weight Slot） | 每笔 ¥30K，模拟"每个持仓等权重" |
| **最大仓位数** | 8 | 对应 80 万总仓位上限（¥30K × 8 = ¥24万，实际总资金 ¥100万） |
| **再平衡** | 无主动再平衡 | 仅通过清仓释放现金后自然再平衡 |
| **杠杆** | 无 | 满仓约 24% 仓位利用率 |

### 1.5 入场品种筛选

- **评分来源**：与面基共用 `SCORE_MAP`（19只标的的六因子评分，但代码中评分是**预先设定好的静态值**，没有逐日变化）
- **评分是静态的**：`build_daily_snapshots()` 中 `sm[sym] = SCORE_MAP.get(sym, {}).get("score", 5.0)` — **评分在整个回测期内不变**
- **依赖的技术数据**：无需额外筛选，只用评分排序

### 1.6 优势

1. **风控层次丰富**：4层卖出保护覆盖亏损、浮盈回吐、技术恶化、基本面恶化四种场景
2. **量化阈值清晰**：-8% 止损 / -12% 回落止盈都是实盘常见参数，经过实证验证
3. **回撤控制优秀**：硬止损 + 峰值回落双重保护，理论上最大单笔亏损锁定在 -8%~-12%
4. **逻辑简洁**：无复杂的辩论/投票机制，代码可维护性强

### 1.7 劣势

1. **建仓缺少技术面过滤**：对比面基的 `if ma60_dev <= ma20_dev and score < 5.5: continue`，SilverQuant 在评分刚过线但趋势向下时仍会入场
2. **评分静态问题**：回测中评分不变，导致 ScoreDropSeller 永远不触发。实际使用时需每日更新评分
3. **仓位利用率低**：¥30K × 8 = ¥24W，资金利用率仅 24%，在大牛市会大幅跑输
4. **无再平衡机制**：持仓品种间的权重会因涨跌偏离初始等权
5. **MASeller 的 -5% 豁免条件可能过于复杂**：均线死叉 + 已亏超-5%时不卖，实际上在"死叉确认 + 深套"时选择了死扛

### 1.8 改为「每周最多交易1次」需要调整的规则

| 需要调整的点 | 具体修改 |
|-------------|----------|
| **建仓频率限制** | 每天扫候选 → 改为每周一扫描一次，本周内不重新排序 |
| **清仓频率限制** | 每日清仓检查可保留（风控不应受周频限制），但卖出后该周不可再买入同一标的 |
| **评分更新频率** | 评分改为周频更新，而非每日读取静态值 |
| **MA死叉信号** | 周频下 MA 信号滞后更严重，建议改用周线级别 MA 判断 |
| **止损检查** | 硬止损和回撤止盈应保留每日检查（风险控制不能降频） |
| **槽位再平衡** | 如果每周只交易一次，需要在周初重新计算各标的仓位分配 |

### 1.9 应用到A股需要的数据输入

| 数据 | 来源 | 频率 | 用途 |
|------|------|------|------|
| 股票收盘价（后复权） | 聚宽/Tushare/AkShare | 日频 | 计算 PnL、止损、MA |
| 股票评分（六因子） | 面基扫描系统 | 日频或周频 | 建仓排序 + ScoreDropSeller |
| MA20 / MA60 偏离度 | 由收盘价计算 | 日频 | MASeller 触发条件 |
| 个股所属板块/市值 | 基础信息 | 静态 | 评分因子的一部分 |
| 交易量/换手率 | 聚宽/Tushare | 日频 | 可选扩展（原版有 VolumeDropSeller 但回测未启用） |

## 二、TradingAgentsStrategy（辩论制策略）

### 2.1 核心逻辑（一句话）

> **多角色辩论裁决：对每个标的模拟 Bull / Bear / Neutral 三个"Agent"打分，Research Manager 综合裁决后形成最终辩论分，结合 Kelly 公式动态分配仓位，风控也依赖辩论分。**

### 2.2 建仓规则

| 维度 | 规则 | 阈值/参数 |
|------|------|-----------|
| **候选池** | 全市场非持仓标的按辩论分降序 | TOP 3（建仓面更窄） |
| **辩论分门槛** | 辩论分 ≥ 5.5（高于面基的5.0） | `ds < 5.5 → continue` |
| **仓位上限** | 集中度高 | `max_positions = 6` |
| **仓位大小** | **Kelly公式**动态计算 | 详见下文 |
| **单笔上限** | 单笔不超过总资金的 12% | `min(kelly, 0.12)` |
| **最小手数** | 100股 | `max(100, int(pc/price/100)*100)` |
| **现金约束** | 现金不足直接跳过（不缩量） | `cost > self.cash → continue` |

**辩论分计算过程（`_debate` 函数）**：

```
bull = score × 0.5 + total_tech_score × 0.5
bear_penalty = (1.0 if MACD死叉) + (0.5 if RSI>70)
bear = score - bear_penalty
neutral = score

# Research Manager 裁决：
if bull ≥ bear AND bull ≥ neutral:
    final = bull × 0.6 + neutral × 0.3 + bear × 0.1
elif bear ≥ bull AND bear ≥ neutral:
    final = bear × 0.5 + neutral × 0.3 + bull × 0.2
else:
    final = neutral

final = clamp(0, 10)
```

**key observation**：bull 总是 ≥ bear（因为 bull = (score + tech_score)/2，而 bear = score - penalty，penalty 最多 1.5），所以**绝大多数情况下 bull 胜出**，`final = bull×0.6 + neutral×0.3 + bear×0.1`。实际结果是辩论分 ≈ 基本面和技术面的加权平均，略偏向基本面。

**Kelly 仓位公式**：

```
win_prob = min(辩论分 / 10.0, 0.8)
kelly_raw = (win_prob * 1.8 - (1 - win_prob)) / 1.8   # 赔率设为 1.8:1
kelly_final = kelly_raw * 0.5                          # 半凯利，降低波动
position_cash = cash * min(kelly_final, 0.12)           # 上限12%
```

| 辩论分 | win_prob | 半凯利比例 | 单笔金额(¥100W总资金) |
|--------|----------|-----------|----------------------|
| 5.5 | 55% | 8.6% | ≈ ¥86,000 |
| 7.0 | 70% | 19.4% → capped 12% | ¥120,000 |
| 9.0 | 80% | 27.8% → capped 12% | ¥120,000 |

### 2.3 清仓规则（3个条件，按优先级）

| # | 条件 | 触发条件 | 数学公式 | 说明 |
|---|------|----------|----------|------|
| 1 | **辩论分强卖** | 辩论分 < 4.0 | `dscore < 4.0` | 辩论裁决明确看空，无论盈亏 |
| 2 | **硬止损** | 浮动亏损 ≥ -8% | `pnl_pct ≤ -8` | 与SilverQuant相同的止损线 |
| 3 | **弱持仓** | 辩论分 < 5.0 **且** 处于亏损 | `dscore < 5.0 AND pnl_pct < 0` | 不看好 + 亏损中 → 及时止损 |

**关键差异**：TradingAgents **没有** FallSeller（峰值回落止盈）机制。这意味着盈利的标的如果辩论分一直 ≥ 5.0，会一直持有直到盈利变亏损或辩论分下滑。

### 2.4 仓位管理

| 维度 | TradingAgents | 对比 SilverQuant |
|------|---------------|------------------|
| **模式** | Kelly公式（半凯利） | 固定槽位 |
| **最大仓位数** | 6 | 8 |
| **单笔最大** | 12% 总资金 | 3%（固定¥30K） |
| **资金利用率** | 最高 72%（6×12%） | 最高 24%（8×3%） |
| **单票集中度** | 高（12% ≈ ¥12万） | 低（3% ≈ ¥3万） |
| **动态调整** | 是（辩论分→Kelly动态） | 否（固定¥30K） |

### 2.5 入场品种筛选

- **辩论制评分**：不仅依赖于六因子评分，还叠加了技术信号（MACD、RSI）作为修正
- **技术面权重**：占 bull 得分的 50%，影响整体入场排序
- **评分来源**：与面基共用 `SCORE_MAP`，技术面指标在 `build_daily_snapshots()` 中实时计算

### 2.6 优势

1. **动态仓位管理**：Kelly公式让"高确信度"的标的获得更大仓位，理论上信息比更优
2. **多维度信号融合**：辩论制将基本面评分和技术面信号有机结合，而非简单的评分排序
3. **集中度更高**：6个仓位 × 12%上限，相比面基/SilverQuant更集中，在正确方向上收益弹性大
4. **弱持仓止损独特**：`辩论分<5.0 + 亏损` 双条件卖出，比单一基本面/技术面判断更稳健
5. **建仓门槛更高**（5.5 vs 5.0），天然过滤掉边缘标的

### 2.7 劣势

1. **辩论分算法在bull几乎永远胜出**：`bull = (score + tech) / 2`，`bear = score - 1.5`（死叉+超买全触发），bull 最少 = (3.5 + 5)/2 = 4.25，bear 最大 = 6.2-1.5 = 4.7，bull 几乎总是 ≥ bear。**裁决结果实际上缺乏辩论性**
2. **无回撤止盈**：缺少 FallSeller 机制，盈利回吐时没有保护
3. **Kelly 赔率参数（1.8）的设定缺乏依据**：为什么是 1.8:1？没有从历史数据校准
4. **RSI > 70 作为 bear_penalty 不合理**：强势股 RSI 长期 > 70 是常态，不应直接扣分
5. **单笔12%上限在实盘中偏高**：A股单票集中度超 10% 需要极高的置信度
6. **MACD 信号在震荡市中频繁金叉死叉**：signals 噪声大，实际效果有限
7. **回测中评分静态**：辩论分在回测中主要受技术指标驱动（因为评分不变），难以反映真实场景

### 2.8 改为「每周最多交易1次」需要调整的规则

| 需要调整的点 | 具体修改 |
|-------------|----------|
| **辩论分更新频率** | 辩论分计算需改为周频更新，macd_signal 和 rsi 使用周线级别数据 |
| **建仓窗口** | 每周一只做一次辩论排序 + 建仓，候选池保持一周不变 |
| **Kelly 仓位计算** | 周频下 Kelly 参数需重新校准（波动率放大） |
| **清仓风控** | 硬止损保留每日检查；辩论分强卖保留每日检查 |
| **弱持仓检查** | 可降为周频（辩论分+亏损是慢变量） |
| **MACD信号** | 切换到周线 MACD，避免日线噪声 |

### 2.9 应用到A股需要的数据输入

| 数据 | 来源 | 频率 | 用途 |
|------|------|------|------|
| 股票收盘价（后复权） | 聚宽/Tushare/AkShare | 日频 | 价格、PnL、RSI、MACD |
| 股票评分（六因子） | 面基扫描系统 | 日频/周频 | 基本面评分（辩论输入） |
| MACD 信号 | 由收盘价计算 | 日频 | bear_penalty 判定 |
| RSI(14) | 由收盘价计算 | 日频 | bear_penalty 判定 |
| MA20/MA60 | 由收盘价计算 | 日频 | total_tech_score 计算 |
| 全部市场标的评分 | 扫描系统 | 日频 | 辩论排序需要全市场数据 |

### 3.2 与面基当前策略的核心差异

#### SilverQuant vs 面基

| 差异点 | 面基 | SilverQuant | 影响评估 |
|--------|------|-------------|----------|
| **趋势过滤** | ✅ 建仓时有 MA60/MA20 纠偏 | ❌ 无 | SilverQuant 更容易在下跌趋势中接盘 |
| **硬止损** | ❌ 无 | ✅ -8% | SilverQuant 单笔风险可控 |
| **峰值回落** | ❌ 无 | ✅ -12% | SilverQuant 能锁定浮盈 |
| **MA卖出条件** | 评分<5时MA死叉即卖 | 评分<5 + 亏损<5%时才卖 | SilverQuant 更宽容，会多扛一下 |
| **评分下滑卖出** | 评分<4.0 | 评分<4.5 | SilverQuant 对评分下滑更敏感 |
| **总结** | SilverQuant 用**多层量化风控**替代了面基的**趋势过滤+简单评分阈值**。面基更依赖基本面判断（入场时趋势纠偏，出场时评分低才卖），SilverQuant 更依赖价格行为（硬止损、回撤止盈） |

#### TradingAgents vs 面基

| 差异点 | 面基 | TradingAgents | 影响评估 |
|--------|------|---------------|----------|
| **建仓依据** | 纯评分排序 | 辩论分（评分+技术融合） | TradingAgents 多一层技术过滤 |
| **建仓门槛** | 评分≥5.0 | 辩论分≥5.5 | TradingAgents 入场更谨慎 |
| **仓位分配** | 固定¥30K | Kelly动态（最大¥120K） | TradingAgents 弹性大，高确信度重仓 |
| **清仓依据** | 评分<4 / MA死叉 | 辩论分+硬止损+弱持仓 | TradingAgents 清仓逻辑更复杂 |
| **品种集中度** | 8只×3% = 24%仓位 | 6只×12% = 72%仓位 | TradingAgents 集中得多 |
| **技术面权重** | 仅用于MA纠偏 | 占辩论分50%权重 | TradingAgents 技术面影响更大 |
| **总结** | TradingAgents 核心差异在于**动态仓位（Kelly）+ 多信号融合（辩论制）**，理论弹性更大但复杂度也更高。面基更注重防守（趋势过滤+低集中度），TradingAgents 更注重进攻（高集中度+重仓机会） |

## 四、源码逐行核心逻辑解析

### 4.1 SilverQuantStrategy（backtest_v2.py L133-175）

```
L133-136: class & __init__
    - 继承 BaseStrategy，设置 entry_threshold=5.0 (建仓评分门槛)
    - max_positions=8 (最大持仓数)

L137-151: daily_step 建仓部分
    L138: held = set(self.positions.keys()) → 获取当前持仓symbol集合
    L139: cands = sorted(...score...reverse)[:5] → 非持仓标的按评分降序取TOP5
    L140-141: len(positions) ≥ max_positions → 达到上限就停止建仓
    L142: score < entry_threshold → 评分未达标跳过
    L143-144: price ≤ 0 → 无效价格跳过
    L145: qty = max(100, int(30000/price/100)*100) → 固定¥30K/槽位，取整到100股
    L146-148: cost > cash 时缩量至可用现金
    L149-150: 扣减现金，记录持仓（entry_price, quantity, entry_date, peak, current_price）
    L151: 记录交易日志

L152-174: daily_step 清仓部分（核心差异）
    L153-155: pos["current_price"] = price; pos["peak"] = max(peak, price)
    L156: 提取 entry 和 peak
```

## 五、总结与建议

### 5.1 各策略最适合的场景

| 策略 | 最适合市场 | 最不适合市场 |
|------|-----------|-------------|
| **SilverQuant** | 震荡市/温和下跌市 | 单边大牛市（止损频繁踏空）|
| **TradingAgents** | 结构性牛市（有大α机会）| 震荡市（Kelly重仓进出导致频繁摩擦）|
| **面基（当前）** | 稳健风格、回撤敏感型 | 快速上涨行情（仓位太保守）|

### 5.2 代码层面的潜在缺陷

1. **评分静态**：所有策略回测中 `SCORE_MAP` 是固定值，ScoreDropSeller / 辩论评分在回测中表现失真
2. **数据窗口短**：仅60日回测，不足以评估策略在完整牛熊周期中的表现
3. **无交易成本**：未计入滑点、印花税（A股卖出0.1%）、佣金（约万1.5）
4. **TradingAgents Kelly 赔率参数 1.8**：没有从历史数据回测校准，随意性较大
5. **无流动性限制**：未检查标的日成交额，小盘股可能无法按信号价格成交

### 5.3 推荐改进方向

1. **融合 SilverQuant 的风控组件到面基**：建议保留面基的趋势过滤建仓 + 叠加 SilverQuant 的 HardSeller(-8%) 和 FallSeller(-12%)
2. **TradingAgents 的 Kelly 仓位值得借鉴**：但赔率参数需根据 A 股历史波动率校准（建议用过去252日收益标准差）
3. **动态评分**：所有策略都需要真实逐日评分变化才能正确评价
4. **周频改造**：对于换手率敏感的投资组合，统一限制每周1次建仓 + 保留每日止损
