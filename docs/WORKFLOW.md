# 面基投资系统 · 开发工作流

> **版本**: v2026.07.03 | 与飞书文档同步
> **核心理念**: 用户只做选择题，不读长文档

---

## 一、核心理念

```
旧方式（Superpowers 重包装）:     新方式（grill-me + Trellis）:
Agent 写 2000 字方案              Agent 问问题
→ 用户读、纠错                     → 用户选答案（2-3选1）
→ Agent 改、用户再读               → Agent 执行
→ 脑力高（评估性思考）              → 脑力低（识别性思考）
→ 首遍精度 ~50%                    → 首遍精度 ~85%
```

**三个原则**：
1. **选择题 > 填空题** — 永远给选项，不写长文档
2. **先问清再动手** — 需求不明确时先 `/grilling`，不跳过
3. **事后补文档** — 代码先改，文档后补，不要为了写文档而卡开发

## 二、完整工作流（3 阶段，精简版）

### Phase A: 需求澄清 → 你拍板 🎯

不是我写方案你读，而是**我问你答**：

```
Agent: "关于这个任务，我想确认几个点。每个点给你 2-3 个选项，你选就行。"

Q1: 这个功能是要 A/B/C 哪个？
  → 你选 A

Q2: 优先级是 P0/P1/P2？
  → 你选 P0

Q3: 影响范围是 X 还是 Y？
  → 你选 X

→ 共识达成，进入执行
```

**产出**: 一个飞书文档（3-5 段，不超过半页），记录你的选择
**耗时**: 2-3 轮对话，不是 2000 字的方案文档

### Phase B: 分步执行 → TDD 🛠️

```
┌─ Task 1 ─────────────────────────────┐
│  写测试 run → fail                    │
│  实现 run → pass                      │
│  commit                              │
├─ Task 2 ─────────────────────────────┤
│  ...                                 │
├─ Task N ─────────────────────────────┤
│  ...                                 │
└──────────────────────────────────────┘
```

- 每个 Task 2-5 分钟，TDD 循环
- 不需要提前写完整计划文档
- 每步完成后自动 commit

### Phase C: 自动补文档 📝

代码改完后：
1. Agent 自动生成/更新 `docs/` 下对应 MD
2. 更新 `README.md` 链接（如果需要）
3. Tag 锁版本

**不阻塞开发** — 文档是事后产物，不是事前要求

## 三、工具链

| 阶段 | 工具 | 用法 |
|------|------|------|
| 需求澄清 | **grill-me** (Matt Pocock Skills) | Agent 追问 → 你选答案 |
| 提案 & Spec | **OpenSpec** `/opsx:explore` | 读代码 → 问问题 → 写 Spec |
| 任务树 + 上下文 | **Trellis** | 执行阶段拆任务、治理上下文 |
| 执行 | **Hermes Agent** | TDD + delegate_task |
| 文档 | **Hermes write_file** | 事后补 docs/ |

## 四、飞书文档的用法

飞书不再存放长方案文档。每个改动的飞书文档结构：

```
标题: [功能名] · 决策记录

## 背景（2行）
## 选项（每个 1-2 行）
   A. 方案A — 优点/缺点
   B. 方案B — 优点/缺点
## 决策
   → 选 A
## 执行计划（不超过 5 个 bullet）
```

你只需要：**在选项上画√**。然后在评论里说"开干"。

## 五、质量标准（精简版）

| 优先级 | 规则 | 触发条件 |
|--------|------|---------|
| P0 | 硬编码凭证 -> 环境变量 | 每个改动检查 |
| P0 | 纯函数必须有测试 | strategies/ 新建/修改时 |
| P1 | docs/ 文档事后补 | PR 合并前 |
| P2 | 删除重复代码 | 重构时顺便 |
