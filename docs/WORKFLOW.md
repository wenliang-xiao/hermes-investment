# 面基投资系统 · 开发工作流 v4（四合一）

> **版本**: v2026.07.03 | 代替 v3
> **核心理念**: 按范围选工具——复杂飞书评审，中小 grill-me，统一 Trellis 执行

---

## 一、四套工具，各管一段

```
工具          最佳场景                   你的角色
──────────────────────────────────────────────────────────
OpenSpec      复杂项目、架构决策、多模块  审飞书文档+评论批注 (你擅长这个)
Superpowers   brainstorm → plan 结构     把控大方向
grill-me      中小改动、设计细节选择题    做选择题(A/B)，10-15分钟
Trellis       执行阶段拆任务+上下文治理   审核拆分方案
```

**不是替代关系，是组合关系。** 复杂项目走 OpenSpec 飞书评审车道，中小改动走 grill-me 快速车道——两条车道在 Trellis 执行阶段合并。

---

## 二、双入口工作流

```
                   你的需求
                       │
               ┌───────┴───────┐
               ↓               ↓
          ┌─────────┐    ┌─────────┐
          │ 复杂项目 │    │ 中小改动 │
          │ (跨模块/ │    │ (单模块/ │
          │ 架构级)  │    │ 功能级)  │
          └─────┬───┘    └────┬────┘
                ↓              ↓
     ┌──────────────────┐  ┌──────────────────┐
     │ OpenSpec 飞书蓝图 │  │ grill-me 追问    │
     │ Agent 写方案文档  │  │ Agent 问选择题   │
     │ 你 review+评论    │  │ 你选 A/B         │
     │ 迭代至共识        │  │ 10-15分钟共识    │
     └────────┬─────────┘  └────────┬─────────┘
              ↓                     ↓
              └──────────┬──────────┘
                         ↓
              ┌──────────────────────┐
              │ Trellis 纵向切片     │
              │ 拆为 AFK/HITL 任务   │
              │ 你审核拆分方案       │
              └──────────┬───────────┘
                         ↓
              ┌──────────────────────┐
              │ TDD 执行 + commit    │
              │ 每个切片：测试→实现   │
              └──────────┬───────────┘
                         ↓
              ┌──────────────────────┐
              │ 事后补文档+打tag     │
              └──────────────────────┘
```

### 入口 A：复杂项目 — OpenSpec 飞书评审流程

适合：跨模块重构、新策略引入、架构决策、需要你深度思考的改动

```
1. Agent 读代码 → 写飞书方案文档（含背景、选项、影响评估）
2. 你在飞书上加评论（批注哪些对/哪些不对）
3. Agent 读评论 → 修改方案 → 你确认
4. 你说"开干" → 进入 Trellis 执行
```

飞书文档格式：

```
标题: [复杂功能] · 设计提案

## 背景（3-5行）
## 现状分析
## 方案选项（2-3个，每个含优/缺）
## 影响范围
## 执行计划（粗粒度阶段）
```

你在这个流程里：**审文档 + 加评论批注**。这是你最擅长也最认可的 review 模式。

### 入口 B：中小改动 — grill-me 快速通道

适合：单模块修改、已有方案内的功能点、确定方向后的细节

```
Agent: "关于这个改动，确认几个点——"
Q1: A方案/B方案？   → 你选
Q2: P0/P1？         → 你选
Q3: 范围 X/Y？      → 你选
→ 共识达成 → 直接进入 Trellis 执行
```

你在这个流程里：**做选择题**。10-15 分钟，不写文档。

### Trellis 执行（两个入口共用）

```
Agent 拆为 3-5 个纵向切片
每个切片：
  - 端到端可独立验证
  - 标注 AFK（Agent自动）或 HITL（需你参与）
你审核切片方案（2 分钟）
→ Agent TDD 逐个执行
→ 每个切片：测试→失败→实现→通过→commit
→ 遇到复杂bug → diagnose（先建 pass/fail 信号）
```

### 事后补文档（两个入口共用）

```
代码完成 → Agent 自动：
  1. 更新 docs/ 对应 MD
  2. 更新 README 链接
  3. 打 tag 锁版本
```

## 三、选择指南

| 判断标准 | 走 OpenSpec 飞书评审 | 走 grill-me 快车道 |
|----------|-------------------|-------------------|
| 涉及跨模块改动 | ✅ | ❌ |
| 有多个方案需要比较 | ✅ | ❌ |
| 方向已定，只有细节 | ❌ | ✅ |
| 需要你深度思考架构 | ✅ | ❌ |
| 改动量 < 50 行 | ❌ | ✅ |
| 你当前的脑力状态 | 有余裕看文档 | 想快速推进 |

**优先级**：拿不准时，走 OpenSpec 飞书评审。宁可多一轮 review，不要省掉沟通导致返工。
