# Dashboard 上线前信息架构重设计方案

> 日期：2026-08-31
> 范围：`http://47.85.161.255/dashboard` 整体信息架构（重点覆盖「模拟盘」「回测对比」两个 Tab）
> 目标：把"功能完备的内部数据面板"改造成"以用户任务为中心的决策产品"

---

## 1. 现状问题（一句话诊断）

当前页面是**"后端 12 路由 / 43 端点直接映射成导航"**的工程师视角目录，而不是产品视角的任务流。11 个 Tab 权重相等、无主次，用户打开首页 10 秒内无法回答任何一个核心问题。

---

## 2. 核心任务定义（重构的地基）

### 2.1 用户画像（先明确给谁用）

| 角色 | 核心诉求 | 频率 |
|------|---------|------|
| **主理人（本人）** | 今天该买/该卖什么？组合赚亏多少、为什么？风控是否触发？ | 每日早盘 + 收盘 |
| **策略迭代者（本人/协作者）** | 策略历史表现可信吗？哪个策略值得实盘？ | 周频 |
| （潜在）**团队成员** | 快速了解"系统最近在干嘛、表现如何" | 低频 |

**结论**：产品应该围绕**主理人**的"每日决策闭环"设计首屏，回测等"策略研究"降级为二级入口。

### 2.2 三个核心任务（首屏必须回答）

1. **今日决策**：「今天系统建议我做什么？」——买入/卖出/持有/等待，各几只、为什么。
2. **组合体检**：「我的钱现在怎么样？」——三策略总资产、收益、回撤、风险暴露。
3. **收益归因**：「赚了/亏了，是谁的功劳/谁的锅？」——策略、标的、因子三层归因。

---

## 3. 重构方案

### 3.1 导航重构：11 Tab → 3 组

**现状**（11 个平铺 Tab）：
```
模拟盘 | 回测对比 | 票池 | ETF | 龙虎榜 | 新闻 | 日报 | 证据 | 大师持仓 | 观点
```

**重构后**（按任务分组，主次分明）：

```
【决策】（默认首屏）
  ├─ 今日概览（原"模拟盘"Tab，聚焦后见 3.2）
  └─ 票池（原"票池"）

【研究】（策略迭代者）
  ├─ 回测对比（原"回测对比"，重构见 3.3）
  └─ 因子证据（原"证据"）

【资讯】（辅助信息，默认折叠）
  ├─ 龙虎榜 / 新闻 / 大师持仓 / 观点 / ETF / 日报（合并进二级菜单）
```

**原则**：首屏只留「决策」，「研究」「资讯」收进分组下拉或次级页。龙虎榜、新闻、大师持仓、观点这些"散户资讯味"内容，对主理人的每日决策不是高频刚需，不该和"今日决策"平级。

### 3.2 首屏（今日概览）重构：从"五块平铺"到"结论先行"

**现状**（`dashboard_main.py:130-212` 从上到下）：
```
执行决策区 → 策略总览卡片 → 信号日志 → 净值曲线 → 持仓 → 交易历史
```

问题：① 五块信息平铺，无"今日结论"；② "执行决策区"和"信号日志"是同一批信号的两种视图（见 3.4）；③ 净值曲线不是真净值（见 3.5）。

**重构后**（结论 → 明细 → 工具）：

```
① 今日决策结论条（新增，置顶，一句话）
   "今日：建议买入 2 只（中际旭创、汇川技术），卖出 1 只（宁德时代），
    组合浮亏 −2.13%，三策略均未触发硬止损。"
   （含一个明确的行动 CTA：查看决策明细）

② 组合体检卡片（3 张策略卡，精简）
   总资产 / 当日收益 / 累计收益 / 回撤 —— 砍掉"已投"这种非关键指标，
   胜率改为"平仓 N 笔 / 胜 M 笔"（N<10 显示"样本不足"）。

③ 今日决策明细（合并原"执行决策区"+"信号日志"，见 3.4）

④ 净值曲线（改为真·每日净值，见 3.5）+ 持仓（保留，已是全场最专业的组件）

⑤ 交易历史（默认收起，点开查看）
```

### 3.3 回测对比 Tab 重构：从"空白表单"到"报告列表"

**现状**：打开 Tab 是空态"选择参数后点击运行回测"，用户要手动点按钮等 10s~2min。

**重构后**：
```
① 最近回测结果（默认展示缓存的最新一次，不用等）
   └─ 每行：策略 / 窗口 / Sharpe / CAGR / MDD / 时间 / [打开报告]

② 「新建回测」按钮（折叠参数区，点开才显示表单）

③ 历史报告列表（分组：正式 / 临时，支持删除归档）
```

同时：**三套对比数据源收敛为一个**（保留 evaluator_fixed 引擎，下线 `/comparison` 脏数据页，见 `p0-fix-checklist`）。

### 3.4 消除"执行决策区"与"信号日志"的重复

**现状**（PM 视角最明显的冗余）：

| 视图 | 分组逻辑 | 状态词 | 字段 |
|------|---------|--------|------|
| 执行决策区（`loadExecutionBoard`） | 建议买入/卖出/持有/等待/禁反手 | 置信度、composite | 建仓检查 6 项 + 证据链 5 层 |
| 信号日志（`renderSignalLog`） | 方向/标的/策略/评分/优先级 | 已执行/未执行/待执行 | priority、status |

**重构**：合并为一个"今日决策"表，用**生命周期状态串联**：
```
建议买入(置信度) → 已执行 → 成交价
建议卖出(理由)   → 已执行 → 已实现盈亏
```
信号从"建议"到"执行"用一条记录表达，而不是两个视图各自渲染一遍。

### 3.5 净值曲线：改真净值 + 归属修正

- 数据层：`api_portfolio.py:446-488` 的 `netvalue` 改为**每日 mark-to-market**（现金 + Σ持仓市值），非"已实现盈亏阶梯"。
- 展示层：曲线图标题改为"组合净值"，并叠加沪深300基准（当前模拟盘 Tab 的净值曲线**没有基准线**，回测 Tab 才有——同一产品两套标准）。

## 4. 全局组件修正（横跨所有 Tab）

| 组件 | 问题 | 修正 |
|------|------|------|
| 六层横条（`dashboard_main.py:87-123`） | 常驻所有 Tab，但 `toggleLayerDetail` 是空函数（:1098），点击无反应；L1/L2 编号是团队暗语 | 收进「决策」页顶部，改为用户语言（"市场环境/资产配置/选股/风控/纪律"），补上点击展开或移除点击态 |
| 头部 `runInfo`（:126） | 所有 Tab 共享模拟盘时间戳，切 Tab 信息错位 | 每个 Tab 各自显示数据时间戳 |
| `consistency-bar`（:127） | "🛡️ 数据一致✓"只校验内部会计等式，给错误数据背书 | 扩展校验到数据正确性，否则去掉绿勾 |
| 空态/错误态文案 | "需运行 python3 xxx.py" / "加载失败: e.message" | 产品化文案，去掉运行脚本提示和裸异常 |
| `alert()` / `window.open()` | `runV3Backtest`、`loadEtfDetail` 用原生弹窗 | 改页内卡片 + iframe 内嵌报告 |

---

## 5. 信息架构改造的优先级

| 优先级 | 改动 | 依据 |
|--------|------|------|
| P1 | 首屏"结论先行"重构 + 合并执行决策区/信号日志 | 核心任务不清晰，用户 10 秒拿不到结论 |
| P1 | 回测 Tab 默认展示缓存结果 | 空态开箱体验差 |
| P2 | 11 Tab → 3 组导航 | 功能平铺无主次 |
| P2 | 净值曲线改真净值 + 加基准 | 数据可信度 |
| P2 | 六层横条/头部/状态文案修正 | 细节体验 |

---

## 6. 改造后的验收标准（How we know it's done）

1. 新用户打开首页，10 秒内能回答"今天该做什么"。
2. 首页不存在两个视图渲染同一批信号。
3. 回测 Tab 打开即有结果，无需手动点按钮等待。
4. 所有空态/错误态文案不含"运行 xxx.py"和裸异常信息。
5. 净值曲线为每日 mark-to-market，且叠加基准。
6. 导航从 11 项收敛到 ≤5 个一级入口。
