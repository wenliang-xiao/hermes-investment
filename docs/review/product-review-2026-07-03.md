# Hermes 投资系统 · 专业产品评审报告

> **日期**: 2026-07-03 | **方法**: 深入代码 + Web 抓取 Dashboard + 行业调研（Bloomberg/Wind/iFind/聚宽/米筐/DolphinDB）
> **视角**: 专业量化产品经理 × 资深量化研究员 × 数据架构师

---

## 一、总体定位

Hermes 是一个**个人量化投资辅助系统**，覆盖 A 股 + 港股 + 美股 + ETF，三策略并行，飞书日报推送，FastAPI Dashboard 实时监控。

**核心判断：逻辑框架优秀，工程化严重不足，产品闭环缺失。**

| 维度 | 评级 | 一句话 |
|------|------|--------|
| 因子设计 | B+ | 三层架构合理、19子→7风格、IC加权有想法 |
| 宏观体系 | A- | 双门+四象限+国运线，逻辑链条完整 |
| 因子处理 | D | 无中性化、无行业调整、财务abs()致命错误 |
| 组合构建 | F | 无风险模型、无优化器、无行业限制 |
| 回测系统 | B | 滑点/幸存者偏差/样本外验证，已超90%个人系统 |
| 风控体系 | C+ | 4层止损好，但缺少组合级风控 |
| 策略差异化 | D | 三条策略本质是同一条策略的三种变体 |
| Dashboard UX | C | 7面板功能全但信息割裂，无交易闭环 |
| 日报质量 | B | 内容扎实但80%是重复静态框架 |
| 数据管线 | C | 功能完整但脆弱，pickle风险+零可观测 |
| 安全性 | D | 7处硬编码凭据，公开GitHub |
| 工程化 | D | 零测试、无CI/CD、无依赖管理 |

## 二、最大产品缺口（按影响排序）

### 🔴 缺口1：无组合风险管理（F级，致命）

这是**最大的单点缺失**。整个系统没有任何组合级风险控制：

```
当前: 因子评分 → 排序 → TOP-N → 等权/Kelly分配
专业: 因子评分 → 中性化 → 风险模型(协方差) → 优化器 → 约束求解
```

**具体表现**：
- 不知道当前组合的预期波动率
- 不知道在哪个产业链上集中暴露
- TOP-3全在同一产业链时无任何告警
- 无VaR、无压力测试、无Beta估计

### 🔴 缺口2：Dashboard与日报完全割裂

Dashboard在Web、日报在飞书——两套独立的系统，数据不互通：
- Dashboard首页不展示当日双门状态和调仓建议
- 日报中的15链分析在Dashboard上完全不可见
- 用户每日流程：打开飞书看日报 → 打开Dashboard看信号 → 手动对照

### 🔴 缺口3：无交易执行闭环

Dashboard展示信号但无法执行，`shadow_account.py`的建仓/平仓全是CLI接口：
- 无"信号确认→一键执行"工作流
- 无跟单历史记录
- 止损触发无任何主动通知（用户必须刷新页面才能看到）

### 🔴 缺口4：三相净值为离散交易点

净值曲线只有交易事件时刻的点，没有每日连续快照：
- 无法做任何时间序列分析
- Sharpe/Sortino基于交易事件而非日频收益
- 无法复盘历史调仓决策

### 🔴 缺口5：因子无中性化处理

`standardize_cross_section`只做全截面百分位，不做行业分组：
- Barra标准做法是行业内分组排序（排除行业暴露）
- 当前评分中行业暴露和市值暴露完全不可见、不可控
- `score_symbol`和`score_batch`可能返回完全不同评分

### 🟡 缺口6：三条策略并非真正差异化

faceji/silverquant/tradingagents本质上是同一套因子信号的不同后处理方式：
- 建仓标的重叠度约80-90%
- 真正的差异化应是不同时间框架/因子集/市场/构建方法

## 三、Dashboard专业评审

### 3.1 现状（基于webfetch）

7个Tab面板 + Chart.js图表 + 60s自动刷新。功能覆盖面尚可，但信息架构和交互存在严重问题。

### 3.2 vs 专业工具

| 维度 | Bloomberg Terminal | Wind/同花顺 | 本系统 |
|------|-------------------|------------|--------|
| 实时性 | Tick级毫秒 | 实时/秒级 | 60s轮询，数据源5-15min延迟 |
| 多屏联动 | 浮动窗口任意组合 | 多窗口并排 | 单页面，Tab切换 |
| 操作能力 | 直接下单/条件单 | 条件单/预警 | 纯展示，无交易执行 |
| 历史深度 | 20年+全维度 | 10年+ | 离散交易点 |
| 风险监控 | VaR/Greek/Stress Test | 基础风险指标 | 仅最大回撤 |
| 自定义 | 公式/预警/API | Excel插件/公式 | 硬编码HTML |
| 告警 | 全维度实时 | 价格/异动 | 无Push通知 |
| 导出 | 全格式 | Excel/PDF | 无 |
| 移动端 | 全平台 | 全平台 | 飞书H5（阉割版） |

### 3.3 Dashboard核心问题

| 问题 | 说明 |
|------|------|
| 信息割裂 | 日报在飞书、Dashboard在Web，无交叉链接 |
| 无交易闭环 | 信号展示→执行链路断裂，shadow_account是CLI |
| 刷新破坏状态 | 120s刷新时覆盖innerHTML，用户标签页状态丢失 |
| 数据非实时 | "实时价格"实为最近因子扫描快照 |
| 无导出 | 无CSV/Excel/PDF导出 |
| 无告警 | 止损触发无Push通知 |

## 四、策略体系专业评审

### 4.1 vs 行业标准（Barra/Axioma）

| 维度 | 本系统 | Barra CNE5 | 差距 |
|------|--------|-----------|------|
| 因子覆盖 | 20子因子 | 50-80描述因子+行业+风格+国家 | 大 |
| 因子中性化 | 无 | 行业+市值双中性 | 致命 |
| 风险模型 | 无 | 多因子协方差 | 致命 |
| 优化器 | 等权/Kelly | MVO/BL/风险平价 | 致命 |
| alpha衰减 | 无 | 衰减调整IC | 中 |
| 成本模型 | 分层固定 | 实现差额(I.S.)+市场冲击 | 中 |

### 4.2 三策略真实差异分析

faceji vs silverquant：建仓标的~90%重叠，区别仅在仓位（Kelly vs固定3%）
faceji vs tradingagents：~80%重叠，辩论分略微改变排序
silverquant vs tradingagents：~80%重叠

**建议**：将三条策略改为真正不同维度：
- 策略1：大盘质量（慢速、长持）
- 策略2：小盘动量（中速、高频）
- 策略3：跨资产ETF配置（宏观驱动）

## 五、日报系统评审

### 5.1 内容结构（10板块）

双门状态 → 全球市场 → ETF全景 → 产业链深度 → 新票发现 → 新闻 → 重点票追踪 → 调仓建议 → 面基概念

### 5.2 核心问题

| 问题 | 影响 |
|------|------|
| **80%是静态框架** | 15链配置+投资框架每日重复输出，实际每日动态只占20% |
| **代码量爆炸** | 2575行，15链静态数据占了~50% |
| **飞书API效率低** | 300-600次API调用生成一份日报，5-10分钟 |
| **条件链判断太简单** | 消费电子/新能源车的激活仅看CPI>1.0% |
| **章节编号错乱** | 声明0-9板块，实际编号八/九/十混杂 |
| **无降级策略** | Yahoo Finance不可用时日报失去大部分动态内容 |

## 八、总结

这不是一个"功能不够多"的系统——核心量化模型（三策略、双门、宏观、产业链）的设计思路清晰，回测方法论规范，甚至超过大部分个人量化项目。

**真正的问题在于三个"缺失的闭环"**：

1. **风险闭环缺失**：不知道组合承担了多少风险，不知道风险从哪里来
2. **执行闭环缺失**：信号→决策→执行之间是手动桥梁
3. **反馈闭环缺失**：无法回看历史决策，无法持续改进

补上这三个闭环之后，这是一个可以严格用于个人实盘的系统。
