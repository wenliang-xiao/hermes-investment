# 专业量化回测方法论深度梳理

> 基于 Marcos Lopez de Prado *Advances in Financial ML*、Qlib (微软)、WorldQuant/Two Sigma 思路、Alphalens/pyfolio 标准流程
> 目标：评估我们当前回测水平的差距，给出可行的专业级改造路径

---

## 1. 我们的回测 vs 专业标准：差距评估

### 1.1 数据覆盖

| 维度 | 我们当前 | 专业要求 | 差距 |
|------|---------|---------|------|
| 时间跨度 | 82~189天 (半年) | **3-5 年以上** | 🔴 必须覆盖牛/熊/震荡多周期 |
| 标的数量 | 19~32只 | **100~500+** | 🔴 19只无统计意义 |
| 市场覆盖 | 仅 A 股 | **A+H+US** | 🔴 港股美股缺席 |
| 生存偏差 | 从未处理 | 必须包含退市股 | 🔴 回测收益可能虚高 |
| 财务 PIT | 用 end_date | 必须用 ann_date | 🟡 有前瞻偏差 |

### 1.2 回测方法论

| 维度 | 我们当前 | 专业要求 | 差距 |
|------|---------|---------|------|
| 评估器 | 固定参数 (但82天) | **Walk-Forward 滚动** | 🔴 单窗口无滚动验证 |
| 统计检验 | 无 | **DSR/Bootstrap** | 🔴 无法排除随机性 |
| 成本模型 | 滑点0.1%+佣金 | **按流动性分档冲击** | 🔴 成本严重低估 |
| 多周期 | 无 | **分别讨论牛/熊/震荡** | 🟡 不区分市场状态 |
| 参数敏感性 | 无 | **热力图+平原区选取** | 🟡 单点参数可能过拟合 |
| 行业/市值中性化 | 无 | **Alphalens 标准** | 🟡 因子收益可能来自行业 |

### 1.3 综合评价

> **"我们的回测能筛掉最差的想法，但无法证明一个想法是好的。"**

---

## 2. 需要的改动用一句话说

**现在**：一天的数据 + 一种回测方法 + 一个结果 = "我们信了"
**专业**：多年数据 × 多种方法 × 一个结果 + 置信区间 = "数据驱动决定"

---

## 3. 三步走的路：什么能做、什么不能

### 🔴 我们做不了 / 不值得做的

| 项目 | 原因 |
|------|------|
| 实时停复牌模拟 | 需要交易所直连，我们没那个数据 |
| 精准的 Almgren-Chriss 冲击模型 | 需要 Level 2 逐笔数据 |
| 退市股完整 PIT 数据库 | Wind Level 3 才支持，成本高 |
| Qlib 跨市场完整对接 | 日历系统重写工程太大 |
| 千万级参数网格搜索 | 计算资源不够 |

### 🟢 我们能做到且应该做的

| 项目 | 难度 | 方案 |
|------|------|------|
| **多时间窗回测** | 🟢 | 不改算法，只把 82天 变成 3个滑动+1个持有 |
| **标的扩容** | 🟢 | 32只→89只 (全 WATCHLIST)，外加 30 只沪深300 |
| **港美股补全** | 🟢 | yfinance 拉5年数据，A股 baostock |
| **Walk-Forward 分析** | 🟡 | 把 evaluator_fixed 改成支持 train/test 滚动 |
| **成本模型升级** | 🟡 | 按日均成交额分4档冲击成本 |
| **多周期汇报** | 🟡 | 划分对应窗口覆盖牛熊 |
| **DSR 统计检验** | 🟡 | 加一个 Python 函数的事 |

## 4. 我们到底需要什么样的回测评估系统？

**核心结论：不要推翻现有 evaluator_fixed 架构，而是升级它为多阶段评估系统**

```
               evaluator_fixed.py v2 (升级版)
               ┌──────────────────────────────────────┐
               │  阶段1: 数据准备                       │
               │    源: baostock(A) + yfinance(H+US)    │
               │    覆盖: 3年+ · 89只+ · PIT日期对齐    │
               │    输出: 统一 DataFrame 缓存到本地     │
               ├──────────────────────────────────────┤
               │  阶段2: Walk-Forward 回测              │
               │    窗口: Train{252d}+Test{63d} 滚动   │
               │    回数: 3次×3滚动 = 9轮              │
               │    策略: strategies/*.decide() 纯函数  │
               ├──────────────────────────────────────┤
               │  阶段3: 多周期分解                      │
               │    把回测结果按牛市/熊市/震荡切分汇报   │
               ├──────────────────────────────────────┤
               │  阶段4: 统计检验                       │
               │    DSR + Bootstrap 置信区间           │
               ├──────────────────────────────────────┤
               │  阶段5: 报告输出                       │
               │    JSON 对比表 + 飞书文档               │
               └──────────────────────────────────────┘
```

### 关键改动点

1. **数据层** — 从 baostock 拉满5年日线，缓存到本地
2. **回测层** — 现有的固定评估器跑单次，新增 Walk-Forward 选项
3. **多周期间汇报** — 划分 2023牛/2024震荡/2022熊
4. **统计分析** — DSR + Bootstrap

| 步 | 内容 | 估时 | 产出 |
