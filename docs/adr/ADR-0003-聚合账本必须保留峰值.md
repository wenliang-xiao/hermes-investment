# ADR-0003：聚合账本必须保留峰值 peak

- 状态：Accepted
- 日期：2026-11-03
- 关联：ADR-0004、ADR-0005
- 代码：`scripts/run_trading.py::_aggregate_shadow`

## 背景

四档 Trailing Stop 依赖持仓期内的**峰值价格**（`peak` / `peak_price`）：
浮盈 ≥30% 时峰值回撤 -12% 卖出、10~30% 时 -15%、其余 -20%。

`_aggregate_shadow` 在把三策略状态汇总为 `shadow_account.json` 时，只复制了
`entry_price/current_price`，**丢掉了 peak**。下游（日报/风控展示/Dashboard）
每天拿到的 peak 等于当日价，回撤恒为 0 → Trailing Stop 实际永久失效，
只剩 -8% 硬止损。

## 决策

1. 聚合持仓必须写入 `peak`、`peak_price`、`peak_time`。
2. 同名标的多策略合并时，峰值取**两者较大值**（峰值只会随时间上升，不能被覆盖变小）。
3. peak 缺省时用 `entry_price` 兜底，绝不用 `current_price` 重置。

## 后果

**收益**
- 四档 Trailing Stop 在聚合账本上恢复有效。
- 多策略同标的合并不会因为写入顺序丢失高点。

**代价/风险**
- 账本 schema 增加字段；旧账本读取时按 `pos.get("peak") or entry_price` 兼容。

**范围**
- 影响：`shadow_account.json` 的 `positions[*]`。
- 不包含：`strategy_states.json` 内部已有的 peak 维护逻辑（另有修复）。

## 替代方案

| 方案 | 为什么没选 |
|------|-----------|
| 下游每次重算峰值的近似值 | 没有历史日线无法精确重算，且每天重算成本高 |
| 只用建仓价做回撤基准 | 等于取消 Trailing，只剩硬止损 |

## 验证方式

```python
agg = _aggregate_shadow({"faceji": {"positions": {"600000": {
    "entry_price": 10, "current_price": 12, "peak": 15, "quantity": 100}}}})
assert agg["positions"]["600000"]["peak"] == 15
```

## 回滚方式

移除 `_aggregate_shadow` 中 peak 字段写入即可；已写出的旧账本可保留，缺字段时自动兜底。
