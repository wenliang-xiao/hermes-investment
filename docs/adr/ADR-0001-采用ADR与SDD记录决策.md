# ADR-0001：采用 ADR + SDD 记录本次交易系统加固

- 状态：Accepted
- 日期：2026-11-03
- 关联：[SDD 设计文档](../design/risk-and-ledger-refactor.md)

## 背景

2026-10~11 的审计发现系统存在一批"会亏钱/会算错/无法回退"的问题：持仓被静默删除、
两套账本互相覆盖、风控参数散落在多个文件、关键数据源断链仍继续交易、回测 `--from/--to`
不生效且未计成本。修复横跨策略层、引擎层、脚本层与文档，且部分改动改变了账本文件布局
与对外数字口径。

没有决策记录时，后续维护者无法区分"有意设计"与"历史 bug"，也无法安全回滚。

## 决策

1. 本次及后续同类改动使用 **ADR**（`docs/adr/`）记录决策：背景、选择、代价、替代方案、验证、回滚。
2. 使用 **SDD**：先写设计与输入记录（`docs/design/`），再落代码；新概念同步进 `docs/GLOSSARY.md`。
3. 代码只在注释里引用 ADR 编号，不复制决策正文。
4. 每个 ADR 必须写**可执行的验证方式**和**回滚方式**。

## 后果

**收益**
- 决策可追溯：为什么 fail-closed、为什么拆账本、为什么改回测口径，都能查到。
- 回滚有依据：按 ADR 列出的文件与数据迁移步骤恢复。
- 评审成本下降：同事不必从 diff 反推意图。

**代价/风险**
- 增加文档维护成本；本次一次性补齐 8 条 ADR + 1 篇 SDD。
- ADR 与代码可能不同步，需在评审时检查。

**范围**
- 影响：`docs/adr/`、`docs/design/`、`docs/GLOSSARY.md`、`docs/ARCHITECTURE.md`。
- 不包含：历史三位数 ADR（`ADR-001`～`ADR-005`）的迁移。

## 替代方案

| 方案 | 为什么没选 |
|------|-----------|
| 只写 CHANGELOG | 记录"改了什么"，不记录"为什么/怎么回滚" |
| 只写在 PR 描述 | 仓库无 git 历史（当前为 zip 快照），PR 不可依赖 |
| 不写文档靠代码注释 | 注释分散，跨模块决策无处安放 |

## 验证方式

```bash
ls docs/adr/             # 应包含 README、TEMPLATE、ADR-0001..0008
grep -rn "ADR-000" --include=*.py . | head   # 代码引用编号存在
```

## 回滚方式

文档为纯新增/补充，删除 `docs/adr/` 与本次新增章节即可；不影响运行时行为。
