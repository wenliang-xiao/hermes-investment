# ADR-0004：账本收权：拆分文件 + 迁移旧账

- 状态：Accepted
- 日期：2026-11-03
- 关联：ADR-0002、ADR-0003
- 代码：`output/shadow_account.py`、`scripts/run_trading.py`、`trading/bridge.py`、`scripts/run_event_shadow.py`

## 背景

系统里有两套逻辑同时写同一个 `data/shadow_account.json`：

1. `scripts/run_trading.py`（cron 08:00）把三策略状态聚合成"主账"；
2. `scripts/run_daily.py`（cron 08:30/19:00）的"策略四"通过 `output/shadow_account.py`
   读写同一个文件。

两边字段语义、成本基准、持仓集合都不同，**后跑的会覆盖先跑的**：
策略四的持仓/现金可能被三策略聚合覆盖，反之亦然。审计还发现
`init_portfolio()` 因字段缺失把已建仓账户清空过一次。

## 决策

1. **主账** `data/shadow_account.json` 归 `scripts/run_trading.py`（及其导出桥
   `trading/bridge.py`）**独占写**，打标 `owner="run_trading"`, `schema_version=2`。
2. **策略四账本** 迁移到 `data/shadow_strategy4.json`，归 `output/shadow_account.py` 独占写，
   打标 `owner="strategy4"`。
3. **一次性迁移**：`load_shadow()` 发现新账本不存在、旧账本存在、且旧账本
   `owner != "run_trading"` 且含持仓/历史时，把旧文件整体复制为新账本，写
   `migrated_from="shadow_account.json"` / `migrated_at`。旧文件**不删除**（主账继续使用）。
4. 所有读取方按语义选择账本：
   - 整体模拟盘/三策略 → `shadow_account.json`
   - 策略四 → `shadow_strategy4.json`
   - 价格监控/Dashboard 证据 → 两个都读
5. 写账本统一走 `utils.atomic_io.atomic_write_json`。

## 后果

**收益**
- 两套逻辑不再互相覆盖；每个文件只有一个写者。
- 旧账自动带入策略四，不丢历史。
- Dashboard/告警可同时展示两个账本。

**代价/风险**
- 文件数量增加；读取方必须明确要哪一本账。
- 迁移是**一次性**的：若先跑过 `run_daily` 再跑迁移，可能把旧主账误当策略四历史。
  已用 `owner` 标记 + 含数据判据降低风险。

**范围**
- 影响：`data/shadow_account.json`、`data/shadow_strategy4.json`。
- 不包含：`strategy_states.json`（仍是三策略内部状态）。

## 替代方案

| 方案 | 为什么没选 |
|------|-----------|
| 保留单文件 + 加 `mode` 字段 | 仍是单一写者竞争，覆盖问题不消失 |
| 整库换 SQLite | 迁移面过大，当前优先止血 |
| 只让 run_daily 不写 shadow | 策略四就没有账本，Dashboard 失真 |

## 验证方式

离线（临时目录）：
1. 旧账有持仓、无 owner → `load_shadow()` 生成 `shadow_strategy4.json`，带 `migrated_from`。
2. 旧账 `owner="run_trading"` → **不迁移**。
3. `init_portfolio()` 不清空已有持仓。

生产核对：
```bash
python -c "import json;print(json.load(open('data/shadow_account.json')).get('owner'))"
python -c "import json;print(json.load(open('data/shadow_strategy4.json')).get('owner'))"
# 期望分别是 run_trading / strategy4
```

## 回滚方式

1. 代码回滚到基线 `eb2128f`。
2. 数据：把 `shadow_strategy4.json` 复制回 `data/shadow_account.json`（若需恢复旧行为）。
3. 旧主账从未被删除，可直接继续使用。
