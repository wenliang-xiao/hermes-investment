# 架构决策记录（ADR）

本目录记录对系统行为有长期影响的决策。目的：**让"为什么这么改"可追溯、可评审、可回滚**，
避免后续维护者只能从代码 diff 里猜意图。

## 何时写 ADR

满足任一条件就写：

- 改变风控/资金/账本/回测口径等**影响钱或对外数字**的行为；
- 引入或废弃一个**跨模块约定**（文件归属、字段语义、配置来源）；
- 在两个及以上合理方案之间做了取舍；
- 有意**暂缓**一件事，需要留档说明原因与触发条件。

小 bug、纯重构、样式调整不写 ADR。

## 流程

1. 复制 [TEMPLATE.md](TEMPLATE.md)，按顺序取下一个编号：`ADR-00NN-短横线标题.md`。
2. 至少写清：背景、决策、后果（含代价）、替代方案、验证方式、回滚方式。
3. 代码注释引用 ADR 编号（例如 `# ADR-0006: ...`），不复制全文。
4. 若后续决策推翻旧 ADR：不删旧文件，把旧 ADR 状态改为 `Superseded by ADR-00NN`，新 ADR 里写 `Supersedes`。

## 状态取值

`Proposed` → `Accepted` → （必要时）`Superseded` / `Deprecated` / `Rejected`
