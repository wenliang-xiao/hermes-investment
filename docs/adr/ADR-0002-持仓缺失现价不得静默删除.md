# ADR-0002：持仓缺失现价不得静默删除

- 状态：Accepted
- 日期：2026-11-03
- 关联：ADR-0003、ADR-0004
- 代码：`scripts/run_trading.py`（加载 `strategy_states.json` 处）

## 背景

`run_trading.py` 启动时恢复 `strategy_states.json`。旧逻辑把 `current_price <= 0`
的持仓当成"脏数据"过滤掉：

```python
_kept = {s: p for s, p in positions.items() if (p.get("current_price") or 0) > 0}
```

停牌、行情源失败或字段缺失当天，持仓会被**静默删除**，随后整份状态落盘：
持仓永久消失、没有卖出记录、现金也没有回流。这是一次真实的账户数据丢失路径。

## 决策

1. `current_price <= 0` 时，若 `entry_price > 0`，用建仓价兜底并**保留持仓**，同时打印告警。
2. 只有 `current_price` 与 `entry_price` **都无效**时才丢弃，并显式打印被丢弃的标的。
3. 持仓删除只能由策略卖出/清仓逻辑触发，不允许在"加载状态"阶段发生。

## 后果

**收益**
- 行情抖动不再造成持仓丢失；账户数量与现金守恒。

**代价/风险**
- 兜底现价会让当日盈亏/风控暂时按建仓价计算（偏保守），需靠实时价刷新（Step 6.5）尽快纠正。

**范围**
- 影响：三策略共享的 `strategy_states.json` 恢复路径。
- 不包含：`shadow_strategy4.json`（策略四账本，见 ADR-0004）。

## 替代方案

| 方案 | 为什么没选 |
|------|-----------|
| 继续丢弃脏持仓 | 会永久丢仓，且无任何交易记录 |
| 整份状态回滚到上一备份 | 粒度太大，会连同当日其它策略变更一起丢失 |
| 缺失现价直接清仓 | 把数据故障转成真实亏损，最差选项 |

## 验证方式

离线构造状态文件：一条 `current_price=0, entry_price=10` 的持仓，运行加载逻辑后：

```python
assert sym in restored_positions          # 持仓保留
assert pos["current_price"] == 10         # 建仓价兜底
```

## 回滚方式

恢复 `scripts/run_trading.py` 中旧的三行过滤逻辑即可；无数据迁移。
